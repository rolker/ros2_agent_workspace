# Roadmap template

Template for the **roadmap** kind defined in
[`docs/design/planning_document_vocabulary.md`](../../docs/design/planning_document_vocabulary.md).
Copy the block below to `docs/roadmap.md` in the scope it belongs to (the
workspace root or a project root), delete this heading and these instructions,
and fill it in.

**How to use it**

- Keep it short. A roadmap that becomes a survey of everything stops being read,
  which is the failure this kind exists to prevent. A first cut should fit in
  about 150 lines; anything longer belongs in issues or in *What's not on this
  roadmap*.
- **Every item names its issue as an explicit `#<N>`** — one per row, in its own
  column or immediately after the item text. This is what lets a status-flip
  automation find an item later without the roadmap being reformatted first;
  the sibling `rolker/agent_workspace` runs exactly that against `#<N>` tokens.
  An item with no issue yet uses `—` in that column, never a guessed number.
- Name the parent and the children. A roadmap names the roadmaps beneath it, and
  a child roadmap names its parent; that is how a collection is walked.
- Prioritise items against the scenarios or properties stated at the top, not
  against how recently they came up.

## How this roadmap stays useful

- **Read it at <the scope's forcing function>** — the recurring event that
  makes someone open this file. For a platform repo that is deployment start;
  for the workspace it is the periodic sweep. A roadmap with no forcing function
  goes stale silently, so name the one that applies and say plainly if it is not
  running yet.
- **Read it together with the health document.** The roadmap says where you want
  to go; health says what will stop you. Work appearing in both goes first.
- **Leftovers land here at wrap-up** — things that came up, are not bounded
  enough for an issue, and are not going to be done next time.
- **Prune periodically.** If a deferred item has sat for months with no pull
  toward it, it is dropped, not deferred. Edit it out rather than letting the
  list grow.
- **Mark items done in place**, keeping the `#<N>`, so the loop is visible in
  git history rather than only in the issue tracker.
